Native full CPU MoE validation, client date 2026-10-13

Existing NPU implementation confirmed:
expert_offload_manager.py process_weights_after_loading -> _cast_cpu_weights_to_device_format(mxfp4=True): stack host weights, H2D, restore original orientation, npu_format_cast(29), transpose, copy physical NZ storage back into resident DRAM buffers. Scale load functions also store NPU scale layout. _build_expert_h2d_tasks and _load_expert_weights_into_slots later copy these format-preserving bytes to resident slots; no runtime NZ conversion here. Keeping one native host copy would require changing this NPU upload path, with conversion overhead still unmeasured.

Isolated native_moe.c now computes input Q8_0 quant -> gate/up native dot -> SiLU*up -> Q8_0 quant -> down native dot -> ordered route-weight sum. It borrows separate immutable weight/scale pointers; scratch holds activation bytes and intermediate values only. It does not allocate/copy expert weights. All six input projection/scale arrays are hashed before and after and unchanged.

Known baseline/test limitations:
- Existing grouped code uses 256-row tiles. Initial synthetic hidden=128 produced invalid results because down task count was zero. Test dimensions corrected to 256.
- Reusing the existing backend's shared scratch across synthetic and real sizes in one process triggered heap corruption; separate test processes exit successfully. Cause not yet reduced or repaired; failure logs retained in moe_check.log.
- Existing decode routing source uses the first matching router weight for duplicate expert IDs, unlike grouped route merge. Initial repeated-ID input exposed a discrepancy. Standard top-k uses unique IDs; equivalence suite therefore uses unique IDs. Native implementation sums each route's own weight. This is an existing exceptional-input issue, not evidence of normal top-k corruption.
- Full flow is not all bit-exact due to float accumulation/activation compiler rounding. Tolerances set before final run: F32 normalized peak 2e-5; BF16 1e-2. Detailed case measurements in JSON.
- This is a validated standalone full-compute prototype, not installed serving backend. It is serial and performs defensive scale validation each call; performance optimization, KT worker-pool native integration, owner lifetime/NUMA/pinning and NPU/graph transfer integration remain unimplemented. Timings in logs are harness duration, not serving benchmarks.
